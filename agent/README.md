# Agents SDK starter

This Python package preserves the original plan for locally orchestrated site artifact preparation. The offline path is runnable now. The live path uses the OpenAI Agents SDK to produce advisory planning notes and exercise one read-only capability tool. Actual cloning, native validation and release packaging remain unimplemented.

## Setup

The dependency-free commands in the root README work from source on Python 3.10+. To install the optional SDK, create a virtual environment and use the pinned dependency snapshot:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r agent/requirements-live.txt
$env:PYTHONPATH = "$PWD\agent\src"
.\.venv\Scripts\python -W error -m unittest discover -s agent/tests -v
```

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r agent/requirements-live.txt
export PYTHONPATH="$PWD/agent/src"
.venv/bin/python -W error -m unittest discover -s agent/tests -v
```

`requirements-live.txt` records the versions resolved and checked in a temporary Linux/Python 3.10 environment on October 19. It includes `openai-agents==0.24.0`. It is a version snapshot, not a hash-locked production build, vulnerability approval, or validation on all operating systems. Native Windows installation was not tested. A future deployment must review these packages under the host's dependency policy. `pip install -e './agent[live]'` is an alternative development install; it pins the direct SDK but may resolve different transitive versions.

## Request contract

The JSON request accepts only these fields:

| Field | Meaning |
|---|---|
| `schema_version` | Integer `1` |
| `job_type` | Only `clone_site_artifacts` |
| `donor_site`, `target_site` | Explicit, distinct names; the model cannot choose a donor |
| `donor_backup_ref` | Optional opaque identifier; no backup is loaded by the starter |
| `ipc_address`, `plc_address` | Explicit IP address or null; no discovery or allocation |
| `changes` | Up to 50 textual change proposals; not yet a validated equipment graph |

Requests are limited to 64 KiB. Duplicate/unknown fields and unsupported job types are rejected. The bundled addresses are documentation examples, not real destinations. Do not put credentials or backup contents in a request. The runner reads the explicit request file and writes one explicit new output file.

## Offline examples

```sh
python3 -m site_agent --request agent/examples/site-request.json --output outputs/plan-1.json
python3 -m site_agent --request agent/examples/missing-input.json --output outputs/plan-2.json
```

Offline mode does not import the SDK or use credentials. The complete example reports `BLOCKED_NOT_IMPLEMENTED`. The missing-input example reports `NEEDS_INPUT` and identifies the three absent inputs. Both are generated by application logic, without a model.

## Live planning

Use [the authentication guide](../docs/authentication.md) to choose an approved credential and model. The original design named `gpt-6-astra`; its availability in your account has not been verified. There is no automatic fallback model.

Provide `OPENAI_API_KEY` through your approved environment/secret mechanism and set `OPENAI_MODEL` explicitly. `.env.example` documents the variables; the application does not automatically load `.env` files. Then:

```sh
python3 -m site_agent --mode live --request agent/examples/site-request.json --output outputs/live-plan-1.json
```

Use the corresponding `.venv` Python on Windows or Linux. This command sends the normalized request and tool results to OpenAI and may incur API charges. Use synthetic data for the first authenticated test.

The endpoint is explicitly `https://api.openai.com/v1`. Corporate gateways, custom model providers and proxy policies have not been implemented or tested. An environment variable named `OPENAI_BASE_URL` does not change this starter's explicit endpoint. Network access is controlled by the execution environment, not by the prompt.

The SDK receives the versioned instructions in `instructions.py`, a structured `PlanningAdvice` output schema, and only `get_build_capabilities`. It has no shell, filesystem tool, SSH, database, cloning or deployment tool. Tracing is disabled and model response storage is requested off; this does not override the provider's account-level data policy. Runs are limited to four model turns and 60 seconds; individual HTTP requests use 30 seconds and no automatic retry. These are execution bounds, not a guaranteed dollar budget.

Model output stays under `model_advice`. Application code alone sets job status and the empty artifacts list. A model assertion cannot mark an output ready. The normalized request and policy each have a SHA-256 in the report; raw SDK history and exception text are not persisted. Reports still contain model advice and should be treated as potentially sensitive local data.

## Results and exit codes

| Exit | Meaning |
|---|---|
| `0` | Planning report generated; inspect status because all build adapters remain unavailable |
| `2` | Invalid input/output, absent credential/model, or absent optional dependency |
| `3` | Live model request failed; report uses `AWAITING_AUTH` for authentication failure, otherwise `MODEL_FAILED` |
| `130` | Live operation interrupted; report records `INTERRUPTED` |

Without a key, live mode records `AWAITING_AUTH` before importing the SDK. A model is required even when a credential exists. Missing integration code never returns a fake success. Existing output files are never overwritten. Reports are written with restrictive POSIX permissions where supported; use Windows ACLs on Windows.

## Development and integration

`tools.py` describes four future operations: selected-source acquisition, artifact construction, native validation and release packaging. `request_build()` is an explicit stub and is not registered as a model tool. Connect these to a separately controlled coordinator and pinned `ignProjects` toolchain after implementing typed input/evidence contracts. Do not expose the general Warpgate operator client to the model.

`test_sdk_adapter.py` runs the actual installed SDK against a fake `Model`, exercises a tool-call/result round trip, and verifies structured output without sockets or API credentials. This validates the SDK contract, not authentication or a real model's behavior. The remaining tests require only the Python standard library.

This CLI has no authenticated web UI, durable coordinator, resume/replay protocol, job authorization service, source acquisition, release signing or production adapter. Its output-file convention is a starter, not the complete durable-job design.
